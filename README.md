# Console Load Testing

Консольное приложение для нагрузочного тестирования веб-сайтов.

## Возможности

- **Множественные URL**: Тестирование нескольких URL-адресов одновременно
- **Режимы работы**: Sequential (последовательный) или Random (случайный) выбор URL
- **Виртуальные пользователи**: Имитация одновременной работы нескольких пользователей
- **Заголовки запросов**: Поддержка кастомных HTTP заголовков
- **Статистика в реальном времени**: Облегченные агрегаты без хранения всех результатов в памяти
- **Сохранение результатов**: Потоковая запись результатов в CSV через отдельный writer-поток
- **Анализ результатов**: Загрузка и анализ сохраненных результатов

## Установка

1. Убедитесь, что у вас установлен .NET 9.0 или выше
2. Склонируйте репозиторий
3. Соберите проект: `dotnet build`

## Использование

### Режимы работы

Приложение поддерживает несколько режимов работы:

#### 1. Режим аргументов командной строки

```bash
# Простой тест
app.exe --urls https://example.com --users 5 --requests 10

# С URL заголовками
app.exe --urls https://api.example.com --header "Authorization: Bearer token" --users 10 --requests 50

# Со сценариями (НОВОЕ!)
app.exe --urls https://example.com --scenarios "1:20:3,2:30:5"
```

#### 2. Режим конфигурационного файла

```bash
app.exe --config config.json
```

#### 3. Режим анализа результатов

```bash
app.exe --load results1.csv results2.csv
```

## Параметры командной строки

| Параметр | Короткий | Описание |
|----------|----------|----------|
| `--urls` | `-u` | URL-адреса для тестирования (можно несколько) |
| `--mode` | `-m` | Режим работы: `sequential` или `random` (по умолчанию: sequential) |
| `--users` | `-v` | Количество виртуальных пользователей (по умолчанию: 1) |
| `--requests` | `-r` | Количество запросов на пользователя (по умолчанию: 1) |
| `--delay` | `-d` | Задержка между запросами в миллисекундах (по умолчанию: 0) |
| `--inflight-per-user` |  | Максимум “in-flight” запросов на пользователя (1 = строго последовательно) |
| `--header` | `-H` | Заголовки запроса в формате 'Name:Value' (можно несколько) |
| `--config` | `-c` | Путь к файлу конфигурации (JSON) |
| `--save` | `-s` | Путь для сохранения результатов в CSV файл. Если не указан, создается temp-файл с датой в имени |
| `--load` | `-l` | Пути к файлам результатов для анализа (можно несколько) |
| `--chart-step` |  | Шаг времени для графиков (в секундах). Алиасы: `--chart-time-step-seconds`, `--chartTimeStepSeconds` |

## Конфигурационный файл

Пример конфигурации (`config.example.json`):

```json
{
    "Urls": ["https://example.com", "https://httpbin.org/get"],
    "UrlMode": "Sequential",
    "VirtualUsers": 80,
    "RequestCount": 100,
    "DelayMs": 0,
    "Scenarios": [
        {
            "VirtualUsers": 1,
            "RequestCount": 20,
            "DurationSeconds": 3
        },
        {
            "VirtualUsers": 2,
            "RequestCount": 30,
            "DurationSeconds": 5
        }
    ],
    "UseScenarios": false,
    "CalibrationRequests": 5,
    "ChartTimeStepSeconds": 1,
    "Headers": {
        "User-Agent": "LoadTest/1.0",
        "Accept": "application/json"
    }
}
```

## Вывод результатов

Приложение предоставляет подробную статистику:

- **Успешные/Неуспешные запросы**: Диаграмма распределения
- **Время ответа**: Среднее и 95-й процентиль
- **Статусы HTTP**: Распределение по кодам ответа
- **Статистика по URL**: Детальная информация для каждого URL
- **Графики по времени**: RPS и ошибки в динамике
- **Сводные отчеты**: Анализ нескольких тестов

## Сохранение и анализ результатов

```bash
# Сохранение результатов
app.exe --urls https://example.com --users 10 --requests 50 --save results.csv

# Анализ сохраненных результатов
app.exe --load results1.csv results2.csv results3.csv --chart-step 5
```

Если `--save` не указан, приложение автоматически создаст временный CSV-файл вида `ConsoleLoadTesting_yyyyMMdd_HHmmss.csv` в системной temp-директории и использует его как основной файл результата.

Во время теста результаты пишутся в CSV потоково отдельным writer-потоком. После завершения теста итоговая статистика и графики рассчитываются из файла буферизованным чтением, поэтому приложение не держит все `TestResult` в памяти.

## Технические детали

- **Язык**: C# .NET 9.0
- **HTTP клиент**: HttpClient с поддержкой кастомных заголовков
- **Асинхронность**: Полностью асинхронная обработка запросов
- **Отмена**: Поддержка CancellationToken для корректного завершения
- **Потокобезопасность**: per-user буферы и отдельный поток записи результатов в файл
